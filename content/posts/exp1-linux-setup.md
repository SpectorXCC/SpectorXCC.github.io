### （四）导出 / 导入克隆第二台虚拟机（node2）

利用 VirtualBox 的 OVF 开放格式进行整机备份与克隆部署，搭建双节点测试环境：

#### 1. 导出首台虚拟机（node1）模板
* 彻底关闭正在运行的 `Ubuntu`（node1）系统：
  ```bash
  sudo poweroff
  ```
* 在 VirtualBox 控制面板中选中虚拟机：点击菜单「文件」→「导出虚拟电脑」，格式选择「开放式虚拟化格式 2.0（OVF）」，保存为 `Ubuntu_node1_backup.ova`。

#### 2. 导入生成第二台虚拟机（node2）
* 点击「文件」→「导入虚拟电脑」，载入刚导出的 `.ova` 包，虚拟机命名为 `Ubuntu_node2`。
* **关键选项**：在导入参数设置中，将「MAC 地址策略」切换为 **“为所有网卡重新生成 MAC 地址”**（Generate new MAC addresses for all network adapters），防止两台机器因网卡物理地址完全相同而在虚拟交换机中发生 ARP 广播冲突与 IP 抢占。
* 完成导入后，启动 `Ubuntu_node2`。

#### 3. 启动 node2 并完成网络与节点标识重置
启动第二台虚拟机进入系统，修改其主机名并验证其独立分配的 Host-Only IP：

```bash

sudo hostnamectl set-hostname node2

# 查看第二台机器的新 IP 地址（确保与 node1 处于同一网段且不重复，例如 192.168.56.102）
ip addr show enp0s8
```

### （五）使用 SSH 从一台虚拟机远程连接另一台

在两台虚拟机均处于开机状态下，开展跨主机远程访问与鉴权实践：

#### 1. 基于密码鉴权的常规 SSH 登录
在第一台机器（node1，`192.168.56.101`）打开终端，通过 SSH 命令直接发起向第二台机器（node2，`192.168.56.102`）的远程安全会话：

```bash
# 格式：ssh 用户名@目标主机IP
ssh caizhouyi2024902186@192.168.56.102
```

* 首次连接系统会弹出远端主机的 ECDSA/ED25519 指纹确认提示：输入 `yes` 并回车。
* 输入远端用户的登录口令，回车后提示符变为 `caizhouyi2024902186@node2:~$`，标志已成功登录远端。
* 在远端会话中执行基础系统检测指令：
  ```bash
  hostname
  uname -a
  exit
  ```
  输入 `exit` 后终端退回到 node1 本地会话。

#### 2. 基于非对称密钥的免密登录配置（进阶实践）
口令交互认证在大规模集群自动化运维时较为低效且存在被嗅探暴力破解的风险。改用 RSA/ED25519 非对称公私钥对建立单向免密互信通道：

```bash
# 1. 在 node1 本地生成 2048 位 RSA 密钥对（一路回车使用默认路径且密码留空）
ssh-keygen -t rsa -b 2048

# 2. 将 node1 生成的公钥追加注入到 node2 的 ~/.ssh/authorized_keys 中
ssh-copy-id caizhouyi2024902186@192.168.56.102

# 3. 再次连接 node2，此时直接跳过密码提示完成身份校验并登录
ssh caizhouyi2024902186@192.168.56.102
```

> * **截取内容**：在 node1 终端中通过 SSH 登录 node2、执行 `hostname`、`uname -a` 以及退出（或免密登录测试）的完整交互过程。

## 三、思考题

### 1. 为什么要使用虚拟机安装 Linux？直接安装物理双系统有什么优缺点？

在日常学习与开发中，虚拟机与物理双系统是接触 Linux 的两种主流路径，但两者定位与权衡截然不同：

* **使用虚拟机的核心原因**：
  1. **环境隔离与容错边界极高**：在学习底层内核参数、系统级网络管理或提权操作时，一旦配置失误导致系统损毁，只需一秒回滚快照或重建副本，绝不会威胁宿主机已有的操作系统与个人核心数据。
  2. **多节点拓扑构建极其灵活**：单台笔记本通过划分虚拟网卡，即可在几分钟内虚拟出一个包含多个节点的局域网络，进行分布式集群、SSH 免密跳板、负载均衡等真实工程练习，物理单机单系统根本无法达成这种网络拓扑。
  3. **硬件兼容门槛低**：虚拟化层将底层异构的物理 Wi-Fi、声卡、蓝牙等设备封装为通用的虚拟网卡与控制器，完全绕过了 Linux 在部分笔记本新型硬件上常见的驱动缺失问题。

* **物理双系统的优缺点分析**：
  * **优点**：能够独占全部 CPU、物理内存与 GPU 算力，无虚拟化调度的性能损耗，在运行高负载深度学习框架或需要原生物理显卡直通的游戏/渲染场景下表现最优。
  * **缺点**：安装与维护风险大，引导加载项（如 GRUB 与 Windows Boot Manager）容易因系统升级损坏导致双向无法开机；两套系统切换必须重启，无法同时并行查阅资料与编码。

### 2. 如果两台虚拟机无法互相 ping 通，应该按照什么次序排查与解决？

虚拟机间网络不通通常集中在链路层、网络层或主机防护规则上，应遵循“自底向上”的标准化链路排查流程：

1. **检查虚拟网卡工作模式是否一致（物理/拓扑层）**：
   * 确认两台虚拟机的通信网卡是否挂载在同一个虚拟交换机（Switch）上。若一台设为仅主机（Host-Only），另一台设为独立 NAT 且未加入同名 NAT 网络，两者在物理逻辑上处于完全隔离的网络段，根本无法直连。
2. **核对 MAC 地址与 IP 网段（链路层与网络层）**：
   * 执行 `ip addr` 确认两台机器的通信 IP 是否处于同一子网掩码区间（例如均属于 `192.168.56.0/24`）。
   * 重点比对两者的网卡 MAC 地址。如果第二台机器是通过直接复制虚拟机生成的，未重新刷新 MAC，两者会向交换机广播相同的硬件地址引发 ARP 震荡与丢包。
3. **测试本地回环与本地网卡状态**：
   * 在各自机器内先执行 `ping 127.0.0.1` 确认本机 TCP/IP 协议栈运转正常，再 `ping` 自己的内网 IP 确认接口处于 `UP` 状态。
4. **检查防火墙与 ICMP 丢弃策略（安全策略层）**：
   * Linux 默认的 `ufw` 或 `iptables` 可能过滤了 ICMP 回显请求。可暂时执行 `sudo ufw status` 检查状态，或执行 `sudo ufw disable` 测试是否是防火墙规则阻断。

### 3. 导出 OVF 和直接克隆虚拟机有什么区别？各适用于什么场景？

两者在打包机制、存储格式与迁移粒度上存在差异：

| 比较维度 | 导出 OVF / OVA | 直接克隆（完整克隆 / 链接克隆） |
| :--- | :--- | :--- |
| **底层实现形式** | 基于 DMTF 行业开放式虚拟化标准，将磁盘文件压缩转码（如 VMDK），并将机器元数据（CPU、内存、外设）写入独立的 XML 描述文件，最终打包为一个归档文件 | 在宿主机本地文件系统内，直接通过宿主机管理引擎完整拷贝底层虚拟磁盘镜像（VDI/VMDK）及内部配置文件 |
| **跨平台兼容性** | **极高**。由于遵循通用工业标准，由 VirtualBox 导出的 OVF 可以在 VMware Workstation、ESXi 或 Proxmox VE 等其他平台顺利导入转换 | **低**。仅严格兼容当前虚拟机软件及其相近版本，无法直接搬运到异构虚拟化平台运行 |
| **存储体积与打包耗时** | 导出时通常会对空块进行零压缩并重新封装，单文件体积紧凑（便于移动硬盘或网盘传输），但封包解包耗时较长 | 完整克隆生成的文件体积大；链接克隆体积极小且秒级生成（仅保存快照差异增量），但强依赖母体镜像路径 |
| **典型适用场景** | 课程作业分发、系统长期环境归档、跨团队交付、异构云平台迁移 | 本地开发快速扩展同配置节点、单机多节点集群秒级扩容、测试前快速拉取临时沙箱 |

### 4. 简要阐述 Linux 目录树结构以及常见的目录操作命令。

* **树状目录结构特点**：
  * Linux 摒弃了 Windows 盘符划分（C盘、D盘）的孤岛理念，采用单一根目录 `/` 贯穿全局。无论底层插了多少块物理硬盘，都必须挂载（Mount）到根目录下的某个节点。
  * 核心目录职责划分清晰：
    * `/bin` 与 `/usr/bin`：存放日常交互中高频调用的通用可执行程序（如 `ls`、`grep`、`cat`）。
    * `/etc`：系统核心配置文件聚集区，几乎所有系统服务、网络及软件选项都以明文文本存放在此处。
    * `/home`：各普通用户的私有专属目录基点，用户对其个人目录（`~`）拥有完整读写权限。
    * `/root`：系统管理员（Superuser）的专属家目录，独立于 `/home`，保障单用户救援模式下依然可用。
    * `/tmp`：公开的临时数据中转区，系统定期清理或重启时自动释放。
    * `/dev`：设备映射目录，Linux 将磁盘、终端、键盘等一切外设抽象为虚拟文件节点供上层调用。

* **常见目录操作基础命令**：
  * `pwd`（Print Working Directory）：实时回显当前所处工作目录的绝对定位路径。
  * `cd`（Change Directory）：控制路径跳转。支持绝对路径（如 `cd /var/log`）、相对路径（如 `cd ../dir`）、快速回程（`cd ~` 或单个 `cd` 回家目录，`cd -` 在最近两个历史路径间快速来回跳跃）。
  * `ls`（List Directory Contents）：查看指定目录内的文件清单。常用参数 `-l` 展示长格式属性（权限、用户组、文件大小、修改日期），`-a` 展示包含系统隐藏文件在内的全量内容，`-h` 以符合人类直觉的可读容量单位（K、M、G）呈现。
  * `mkdir`（Make Directory）：构建新目录。配合 `-p` 参数可一次性递归创建多级子树（如 `mkdir -p a/b/c`）。
  * `rmdir`（Remove Empty Directory）：安全移除指定的空目录；若目录内含有内容则自动拒绝，防止误删。

### 5. 虚拟机（Virtual Machine）与容器（如 Docker）在技术原理和主要用途上有何区别？

两者在抽象层次、启动开销与隔离深度上属于两个截然不同的代际技术：

```text
+-------------------------+       +-------------------------+
|     虚拟机 (Hypervisor)  |       |       容器 (Container)   |
|   App A   |    App B    |       |   App A   |    App B    |
| Guest OS  |   Guest OS  |       | Bin/Lib   |   Bin/Lib   |
|  Hypervisor (Type 1/2)  |       |     Container Engine    |
|        Host OS          |       |     Host Linux Kernel   |
|       Host Hardware     |       |       Host Hardware     |
+-------------------------+       +-------------------------+
```

1. **核心架构与隔离机制的区别**：
   * **虚拟机**：通过 Hypervisor（如 KVM、VirtualBox）对底层物理硬件进行**整机硬件级仿真与抽象**。每台虚拟机内部都独立运行一套完整的操作系统内核（Guest OS Kernel），独占自己的虚拟内存空间、中断向量表与驱动栈，与宿主机完全实现硬件级强隔离。
   * **容器**：放弃了对底层硬件与内核的重复模拟，所有运行的容器**直接共享宿主机的主内核（Host OS Kernel）**。利用 Linux 原生内核特性中的 `Namespace` 实现进程间视图隔离（PID、网络、挂载点隔离），结合 `Cgroups`（Control Groups）对容器可占用的 CPU、物理内存上限进行硬性限额，属于**操作系统级进程隔离**。

2. **资源损耗与启动速度对比**：
   * 虚拟机因包含完整的内核引导与系统守护进程启动流程，开机通常需要数十秒到数分钟，即使空载也需常驻占用固定内存（如 2G~4G）。
   * 容器本质上只是宿主机上的一个受限进程，启动速度可达毫秒级，镜像内通常只包含业务二进制代码与依赖动态库，体积常精简在数百兆以内，资源利用率数倍于虚拟机。

3. **适用场景分工**：
   * **虚拟机更适合**：需要测试不同架构或不同内核版本（如在 Linux 物理机上虚拟 Windows）、强多租户安全隔离、系统级内核模块深度开发以及传统大型单体系统的直接托管。
   * **容器更适合**：微服务架构部署、无状态应用弹性伸缩、DevOps 持续集成与交付（CI/CD）以及“一次构建、到处运行”的高一致性跨云分发场景。

---

## 四、实验总结

本次实验完成了基于 VirtualBox 的 Ubuntu 虚拟化环境搭建、网络联通调试及跨主机 SSH 安全互联实践。

在实验起步阶段，理清了虚拟化运行层与客户机资源分配原则。通过同时挂载 NAT 与 Host-Only 双网卡，平衡了虚拟机对互联网资源的拉取需求与局域网内静态 IP 管理的稳定性。在遇到网络无法连通的问题时，掌握了借助 `ip addr`、路由表检查以及 `systemctl` 查询排查网络链路与核心服务状态的方法。

在整机迁移环节，验证了通过 OVF 导出导入快速克隆节点的操作链。体会到了在虚拟网络中重新生成网卡 MAC 地址的必要性——这是保证后续动态 IP 正确租约以及避免网络节点硬件指纹冲突的关键前置条件。

在系统连接与基础操作环节，加深了对 Linux 单根树形目录规范（FHS）与路径定位命令的理解；通过对比 SSH 密码连接与 RSA 密钥对免密认证流程，直观体会到了非对称加密在安全运维与脚本自动化执行中的效率优势，为后续复杂环境下的多节点协作与文件过滤处理奠定了扎实的操作基础。
