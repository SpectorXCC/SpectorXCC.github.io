## 项目定位与设计出发点

**古籍脉络**（Guji Mailuo）是一个面向跨文化阅读场景的中华古籍检索与查证 Web 平台，在线体验地址为 <https://wzmmzs.asia:27888>。

传统的古籍在线阅读与图书馆书目检索往往各自割裂：只做全文搜索时难以核实版本渊源与馆藏著录；只看书目库又看不到对应卷页的上下文原文。古籍脉络尝试将“**发现正文线索 → 关联书目版本 → 核对原始著录与馆藏 → 留存查证路径**”整合成一个透明、可核验的连续工作区。

在视觉设计上，平台以青绿星图墨线（`#244a40`）、宣纸米色（`#f3f0e8`）与印泥朱（`#b74c3d`）作为识别基调，兼顾深浅色主题切换、中英文双语界面以及繁体/简体原字切换。品牌标识由朱砂钤印、穿针装订线、六节点溯源脉络与文悦刻本界栏字体构成，支持静态完整标牌与“钤印落框 → 穿针订线 → 脉络溯源 → 雕版显字”四拍动态入场演绎。

## 双轨检索与正文查证

首页提供**内容发现**与**书目检索**两个独立入口，并各自给出可核验的证据边界：

- **内容发现（知识图谱网 CNKGraph）**：输入篇名、人物或诗文片段（如`欲买桂花同载酒`），按书返回命中摘要并按需展开具体卷次、页码、关键词高亮与前后文；在阅读单书命中时可直接触发“整卷阅读”并跳转原页核对。
- **书目检索（上海图书馆 & 典津）**：普通检索与跨库高级检索并行查询上海图书馆开放古籍接口（`data.library.sh.cn/gj/webapi`）和典津数据（`DIANJIN`），两库分别独立计数、分页与报错，避免把跨库条目直接混淆去重；另有面向“仅上图高级检索”的 6 字段组合面板（题名、主要责任者、版本、批校序跋者、藏印、著录来源）。
- **从正文顺藤查找版本**：在正文详情区利用主书名提取规则与繁简名映射（`features/dianjin/titles.ts`）一键转入“查找这部书的版本”，同时在 URL 与页面快照中保留“返回正文线索”状态，防止线索丢失。

## 三栏交互式查证工作区

检索提交后进入由左、中、右三栏构成的交互式查证工作区（平板与手机端切换为标签分页视图）：

1. **左侧“检索结果”**：按来源展示命中古籍或书目清单，支持独立翻页与分隔线拖拽调节栏宽。
2. **中央“关系图谱”**：基于 `d3-force`、`d3-selection` 与 `d3-zoom` 构建力导向网络（单视图上限 120 个节点）。提交检索后后台逐批拉取作品、责任者、版本、馆藏、藏印、刻工与历史书目著录关联（`depth=1&scope=all`），支持滚轮缩放、节点拖拽排版、选中连线查看关系依据，以及“以此为中心”开启新的探索现场。
3. **右侧“证据详情”**：展示卷次上下文、原始著录直链、馆藏记录及扩展阅读宽区。

## 版本候选与双记录对照

面对同名异版古籍，“同名”并不等同于“同版”。系统按“**作品母类 → 机器候选版本组 → 来源著录 → 馆藏记录**”四层结构组织同一作品：

- 机器自动归并遵循严格保守原则（题名、年代、版本类型、刊刻信息须高度一致；区分影印、重刊等再制说明），所有自动归并组均显式标注“待核”，且只有具备馆藏标识或索书号的记录才列为可定位馆藏。
- 研究者可在右侧详情或宽区视图中任选两条著录加入**并排对照**，系统按题名、责任说明、年代、版本、卷册数量与尺寸逐项标识“著录相符 / 近似 / 资料不全 / 著录有差异”。
- 登录本站账号后，还可以保存仅自己可见的个人版本合并或拆分校核结果。

## 全栈技术栈与工程架构

整个项目采用边缘全栈与本地浏览器存储结合的架构，前后端边界、密钥隔离与缓存策略均有明确划分：

| 层级 | 核心技术与实现 |
| --- | --- |
| 前端框架 | React 19、Vinext / Vite 8、TypeScript 5.9、Tailwind CSS 4、Base UI / shadcn、lucide-react |
| 图谱与汉字处理 | D3（`d3-force`、`d3-selection`、`d3-zoom`）、`opencc-js`（简繁/原字转换） |
| 服务端与持久层 | Cloudflare Workers / Wrangler 运行时、Cloudflare D1 / SQLite、`drizzle-orm` |
| 浏览器本地查证库 | IndexedDB 保存自定义收藏夹、节点证据快照及关系完成状态，支持导出公开 JSON 与 URL 分享 |
| 安全与上游代理 | API 密钥仅由服务端从 `.env.local` 读取（不暴露至前端）；独立账号使用随机盐 + `scrypt` 与 7 天 HttpOnly Cookie |
| 数据缓存设计 | `library_api_cache` 表实现 5 分钟热数据保鲜与最长 24 小时故障降级兜底 |

在 Linux 服务器部署上，项目通过 `server.sh` 对接 `systemd` 管理 `guji.service`（监听本机 `127.0.0.1:3000` 并提供隔离构建切换与失败自动回滚），再由 Caddy 反向代理对公网提供 HTTPS 访问。

## 在线体验与源码目录

- **公网体验地址**：<https://wzmmzs.asia:27888>
- **本地开发与部署方式**：在项目目录配置 `.env.local` 密钥并执行 `npm run db:migrate:local` 完成本地 D1 迁移后，可通过 `npm run local`（或 Windows 下 `start-local.cmd`）启动本地开发服务；Linux 服务器可通过 `./server.sh install` 与 `./server.sh start` 接入 systemd 托管。
